## 二、桌宠篇

### 2.1 路线总览

一条线：**先找「她」**（素材和引擎）→ **把显示拆出来**（三层结构、文件桥）→
**把「她会做什么」一件件接上**（点击反应 → 动作菜单 → 动作语义）→
每一步先做**探针**再动代码。

四个阶段：

| 阶段 | 做了什么 | 关键决定 |
|------|---------|---------|
| 底座 | 上下游的三层结构 | 桌面版是独立 Electron 进程，靠文件桥解耦 |
| 形象 | 精灵图 → Live2D 迁移 | 模型走自定义协议加载；取景按画布量 |
| 交互 | 穿透 / 悬停 / 拖动 | 判定权全部搬进主进程 |
| 会应你 | 九个命中区 + 动作菜单 + 动作语义 | 菜单选的任何新动作，先停下旧的 |

### 2.2 三层结构与文件桥

```
① 插件（大脑）      DSH 进程内：事件状态机、todo 读取、看门狗、RPC
      ↕ 共享文件
② （桥）            pets/xilian/{task.json, state.json, desktop_alive.json}
      ↕
③ 桌宠（显示器）    独立 Electron 进程：只读文件、画模型、做交互
```

- 插件有 Host（进程内）与 Client（页面）两半；**页面半边是动态插件、临时投递的
  （F5 不重新投递）**，桌面版不受影响 —— 这也是「以桌面版为体」的原因之一。
- 心跳与看门狗：桌宠每 5 秒写 `desktop_alive.json`（退出时删掉）；插件的
  petWatchdog 每 5 秒看一次，公式是
  `needPet = !desktopAlive && (!clientAlive || webClosed)`，
  60 秒冷却、且「她刚被关掉」有 10 分钟宽限期（防止用户主动关掉又被立刻拉起）。
  原文（`plugin/host.js`）：

  ```js
  const petWatchdog = () => {
    desktopAlive().then((r) => {
      const now = Date.now()
      const desktop = !!(r && r.alive)
      const webClosed = !!(r && r.webClosed)
      const clientAlive = now - lastClientBeat < 15000
      if (desktop) {
        lastDesktopSeen = now
        exitInfo = null
      } else if (lastDesktopSeen && now - lastDesktopSeen < 10000 && !exitInfo) {
        exitInfo = { at: now, clientWasAlive: clientAlive }   // 她是什么时候被关掉的
      }
      const needPet = !desktop && (!clientAlive || webClosed)
      if (needPet) {
        // 宽限期：她刚被关掉的 10 分钟内不自动拉起
        const grace = !webClosed && exitInfo && now - exitInfo.at < 600000 && !exitInfo.clientWasAlive
        if (!grace && now - lastSpawnAt > 60000) {
          spawnDesktop()
        }
      }
    }).catch(() => {})
  }
  ctx.interval(petWatchdog, 5000)
  ```
- 资产根**运行时探测**，不写死路径：优先部署者显式指定的常量，其次工作区根
  （`sandboxPolicy.workspaceRoot`），最后相对路径。上游文件里曾写着一台别的
  开发机的绝对路径，对任何人都是错的（见坑表 D 组）。

### 2.3 形象：从精灵图到 Live2D

**精灵图时代**（现在仍是回退路径）：

- 素材是 8×9 网格（1536×1872，每格 192×208）。**九行的实际内容与仓库文档假设
  不符** —— 逐行逐帧看过之后再映射，别信文档。
- 桌面端喂 2x 版图（边缘清晰度）。
- 眨眼修复：原实现 120ms 一帧、六帧循环 —— 0.72 秒眨一次眼，其中还有一帧单眼
  wink，看着像眼睛没对齐。改成：稳态只走睁眼帧 [0,1,3,5]、320ms 一帧，
  闭眼帧单独每 6 秒插一次（150ms）。**逐帧动画的循环节拍要按内容设计，
  不能按帧号顺序全轮回。**

**Live2D 迁移**：

- 模型：B站「是依七哒」制作，经 Playa-Cyrene/Cyrene-Agent 分发（粉丝项目授权：
  署名、可改、**非商用**）。**不入 git**，用 `tools/fetch-cyrene-model.ps1`
  下载并按 GitHub API 报的字节数逐个校验（下载坑见坑表 D 组）。
- 运行三件套版本：`pixi.js ^7.3.0` + `pixi-live2d-display 0.5.0-beta`（cubism4
  构建）+ `live2dcubismcore.min.js`。这组版本是从 Cyrene-Agent 的 package.json
  抄的**已验证组合** —— 这类渲染链自己凑版本很费时间，先找一个能跑的参照。
- 脚本加载顺序是硬性的，任何一步断掉都会让 `PIXI.live2d` 缺失、整体回退精灵图：


### 2.4 Live2D 接进 Electron 的四道硬坎

四个都是真障碍（不是调参），按踩到的顺序：

**坎一：`Uncaught ReferenceError: process is not defined`。**
pixi-live2d-display 的 UMD 产物在**求值期**就引用 `process.env.NODE_ENV`，
而渲染进程开着 contextIsolation、没有 nodeIntegration，`window.process` 不存在，
整包抛错、`PIXI.live2d` 整个丢掉。修法是在加载 cubism4 构建**之前**补一个最小垫片：

```html
<script>window.process = window.process || { env: { NODE_ENV: 'production' } }</script>
```

只给 NODE_ENV，不引入任何 Node 能力。

**坎二：`file://` 页面禁止 fetch 本地文件。**
模型加载链（model3.json → moc3 → 纹理 → 表情/动作）全走 fetch，file:// 下全断。
修法：自定义协议 `pet://`：

- `registerSchemesAsPrivileged` 必须在 app ready **之前**调用，privileges 给
  `{standard, secure, supportFetchAPI, stream, bypassCSP}`；
- 窗口用 `loadURL('pet://model/index.html')` 打开，页面与模型同源；
- handler 里 `decodeURIComponent`、路径归一、**前缀校验防穿越**；
  `live2d/` 前缀分流到模型目录，其余落回应用目录。

```js
// 必须在 app ready 之前登记，否则 supportFetchAPI 不生效，fetch 仍会被拒。
protocol.registerSchemesAsPrivileged([{
  scheme: PET_SCHEME,
  privileges: { standard: true, secure: true, supportFetchAPI: true, stream: true, bypassCSP: true },
}])

protocol.handle(PET_SCHEME, async (request) => {
  try {
    const url = new URL(request.url)
    let rel = decodeURIComponent(url.pathname || '')
    if (rel.startsWith('/')) rel = rel.slice(1)
    if (rel === '') rel = 'index.html'
    if (rel.includes('\0')) return new Response('bad request', { status: 400 })

    const useModel = rel.startsWith(LIVE2D_PREFIX)
    const root = useModel ? l2dRoot : appRoot
    const sub = useModel ? rel.slice(LIVE2D_PREFIX.length) : rel
    const abs = path.normalize(path.join(useModel ? LIVE2D_DIR : __dirname, sub))
    if (!abs.startsWith(root)) return new Response('forbidden', { status: 403 })

    return await net.fetch(pathToFileURL(abs).toString())
  } catch (e) {
    return new Response('not found', { status: 404 })
  }
})
```

这个模式对任何「Electron 里要 fetch 本地文件」的场景都通用。

**坎三：给 canvas 设 `width`/`height` 属性 → 模型缩在画布一角。**
canvas 的**绘制缓冲**和**投影矩阵**各算各的，写属性只动了一边。修法：**只设
style 宽高**，画布内部交给库自己管。

**坎四：`cullable` 必须关。**
渲染库的剔除边界按画布矩形算，而模型内容伸到画布矩形之外（发丝、秋千绳），
于是某些动作里她整块被剔没。`cullable = false` 一行解决。

### 2.5 取景：画幅不是窗口，是 canvas

这是整场迁移里最贵的一课，压成三句话：

- **这套模型的画布是 4200×3500**（PixelsPerUnit 3500，画布原点 2100,1750，
  即画幅 1.2×1.0 个单位）。画布本身就是画幅 —— 别拿窗口尺寸猜。
  运行时读法：`internalModel.coreModel.getModel().canvasinfo`。
- 显示尺寸 = **把内容裁框缩放到高度基准**（默认 420px，`PET_L2D_HEIGHT` 可改）。
- 量「内容在哪」试了三种：读 drawable 包围盒（是归一化空间 -1..1 的逻辑盒，
  不是画面）、求顶点并集（发丝与配件的顶点让它失真）、**离屏渲染后扫 alpha
  （唯一可信，最终采用）** —— 阈值 THR=12、MIN_PIXELS=2，裁框留 2% 边距。

三块代码 —— 画布从哪读、内容框怎么量、裁框怎么算：

```js
// 读 Cubism 画布 —— 这就是权威画框。web 框架里没有 csmReadCanvasInfo
//（那是 Native 的 C API），同一个值挂在 coreModel.getModel().canvasinfo 上。
function readCanvas(m) {
  try {
    const im = m.internalModel
    if (!im) return null
    let w = Number(im.originalWidth || im.width || 0)
    let h = Number(im.originalHeight || im.height || 0)
    let info = null
    try {
      const core = im.coreModel
      info = core && core.getModel ? core.getModel().canvasinfo : null
    } catch (e) { info = null }
    if (info) {
      if (!(w > 0)) w = Number(info.CanvasWidth || 0)
      if (!(h > 0)) h = Number(info.CanvasHeight || 0)
    }
    if (!(w > 0) || !(h > 0) || !isFinite(w) || !isFinite(h)) return null
    return {
      w: w, h: h,
      ppu: info ? Number(info.PixelsPerUnit) : null,
      originX: info ? Number(info.CanvasOriginX) : null,
      originY: info ? Number(info.CanvasOriginY) : null,
      // （raw 字段略）
    }
  } catch (e) { return null }
}
```

```js
// 用渲染结果直接量出模型的真实绘制范围：画进离屏纹理，扫 alpha 通道找包围盒。
function measureByRender(appRef, modelRef) {
  const S = 0.05
  const RTW = 1400, RTH = 1400
  let rt = null
  try {
    modelRef.scale.set(S)
    modelRef.x = 0
    modelRef.y = 0
    rt = window.PIXI.RenderTexture.create({ width: RTW, height: RTH })
    appRef.renderer.render(modelRef, { renderTexture: rt })
    const px = appRef.renderer.extract.pixels(rt)
    // 逐列 / 逐行计数，要求「至少 2 个像素」才算数，而不是取第一个 alpha>8 的点 ——
    // 一两个杂散像素就能把包围盒拉宽一倍（上一版因此把左边界量到了 x=440）。
    const THR = 12
    const MIN_PIXELS = 2
    const colHits = new Int32Array(RTW)
    const rowHits = new Int32Array(RTH)
    for (let y = 0; y < RTH; y++) {
      const row = y * RTW
      for (let x = 0; x < RTW; x++) {
        if (px[(row + x) * 4 + 3] > THR) { colHits[x]++; rowHits[y]++ }
      }
    }
    let minX = -1, maxX = -1, minY = -1, maxY = -1
    for (let x = 0; x < RTW; x++) if (colHits[x] >= MIN_PIXELS) { if (minX < 0) minX = x; maxX = x }
    for (let y = 0; y < RTH; y++) if (rowHits[y] >= MIN_PIXELS) { if (minY < 0) minY = y; maxY = y }
    if (minX < 0 || minY < 0) return null
    // 屏幕像素 -> 模型空间：先减去 position，再除以 scale
    return {
      x: (minX - modelRef.x) / S,
      y: (minY - modelRef.y) / S,
      w: (maxX - minX) / S,
      h: (maxY - minY) / S,
    }
  } catch (e) {
    return null
  } finally {
    try { if (rt) rt.destroy(true) } catch (e) { /* ignore */ }
  }
}
```

### 2.6 交互：穿透、悬停、拖动

**点击穿透 + 悬停命中**。窗口大部分是透明的，透明处要点击穿透
（`setIgnoreMouseEvents`）。这里有一个鸡与蛋的死循环：

```
窗口穿透 → 页面收不到 mousemove → 页面不知道光标已进来 → 不取消穿透
```

实测同一个脚本跑两次，一次能拖动、一次一动不动 —— 差别只在桌宠启动瞬间光标
恰好在不在窗口里。修法：**判定权搬进主进程**。页面只负责推「哪些矩形算命中」
（宠物本体内缩 4px、气泡可滚动时整体、关闭按钮可见时），带签名比对去重、
300ms 复检；主进程 60ms 轮询 `screen.getCursorScreenPoint()` 与这些矩形比较，
切穿透状态。拖动期间不判定，另有 30 秒卡死保护（防 drag-end 丢失后一直不判）。

```js
// main.js：判定权在这里。轮询全局光标，与页面推来的矩形比对。
const HOVER_POLL_MS = 60
const DRAG_STUCK_MS = 30000
let hitRects = []          // 窗口客户端 DIP 坐标；由渲染进程推送
let hitIgnoring = true     // 我们**认为**窗口当前是不是穿透态

function startHoverWatch() {
  hitTimer = setInterval(() => {
    const win = petWindow
    if (!win || win.isDestroyed()) return
    // 拖动期间不判定（手快时光标会短暂离开她的矩形）——但守卫本身会变成陷阱：
    // drag-end 丢失后 dragActive 永远是 true、她彻底点不到。所以给它加一个上限：
    // 超过 30 秒的「拖动」一律当作已经结束。
    if (dragActive) {
      if (Date.now() - dragStartedAt < DRAG_STUCK_MS) return
      dragActive = false
    }
    let ignore
    try {
      const p = screen.getCursorScreenPoint()
      const b = win.getBounds()
      const x = p.x - b.x
      const y = p.y - b.y
      let inside = false
      for (let i = 0; i < hitRects.length; i++) {
        const r = hitRects[i]
        if (x >= r.x && x <= r.x + r.w && y >= r.y && y <= r.y + r.h) { inside = true; break }
      }
      ignore = !inside
    } catch (e) {
      return   // 窗口正在销毁 / 显示器在切换，这一拍跳过就好
    }
    // （DRAG_LOG 的诊断行略）
    if (ignore === hitIgnoring) return
    hitIgnoring = ignore
    try { win.setIgnoreMouseEvents(ignore, { forward: true }) } catch (e) { /* ignore */ }
  }, HOVER_POLL_MS)
}
```

**拖动**。位置由主进程算：按下时页面报 CSS 抓取偏移，移动时主进程用
「光标屏幕坐标 − 抓取偏移」算窗口位置。三条钉死的规则：

- 拖动期间**锁尺寸**（dragLockSize），位置用 `setBounds` 全量写 ——
  单写位置（setPosition）会带来 DIP 舍入漂移，窗口在拖拽中一帧长 1px；
- 夹取按**宠物本体**、不按窗口（窗口比宠物多一块气泡区；
  夹窗口会让宠物被留在看不见的地方），四边都留 60px 可见边距；
- 松手 heal 一次尺寸（16px 容差）+ 位置夹取 + 存 `bounds.json`。

```js
// 位置由主进程算：光标屏幕坐标 − 抓取偏移 = 窗口应处的左上角。
ipcMain.handle('drag-move', (e, args) => {
  const win = BrowserWindow.fromWebContents(e.sender)
  if (!win) return
  if (dragOffset) {
    const pt = screen.getCursorScreenPoint()
    const b0 = win.getBounds()
    const off0 = dragOffset
    // 尺寸一律用 drag-start 锁下的那一份，不用 b0 —— b0 正是会漂移的那个值。
    const lock = dragLockSize || { w: b0.width, h: b0.height }
    const wantX = Math.round(pt.x - off0.x)
    const wantY = Math.round(pt.y - off0.y)
    const pos = clampWindowPos(wantX, wantY, lock.w, lock.h)
    // setBounds 而不是 setPosition：显式带上宽高，堵住 DIP↔物理取整带来的漂移。
    win.setBounds({ x: pos.x, y: pos.y, width: lock.w, height: lock.h })
    // 贴边时把抓取点重新锚定到光标上，光标回头时窗口立刻跟着走。
    const clamped = { x: pos.x !== wantX, y: pos.y !== wantY }
    if (clamped.x || clamped.y) dragOffset = { x: pt.x - pos.x, y: pt.y - pos.y }
    // （DRAG_LOG 的诊断行略）
    return
  }
  // （老接口「只送增量」的退路略）
```

```js
const PET_VISIBLE_MARGIN = 60

  const wa = screen.getPrimaryDisplay().workArea
  const M = PET_VISIBLE_MARGIN
  // 宠物在窗口里是底部居中的：偏移按真实布局算，不假定气泡区高度。
  const petTop = Math.max(0, Math.round(h - petSize.h))
  const petLeft = Math.max(0, Math.round((w - petSize.w) / 2))
  const minY = wa.y + M - petTop - petSize.h   // 上边：至少留 M 像素她还在工作区内
  const maxY = wa.y + wa.height - petTop - M   // 下边：同上
  const minX = wa.x + M - petLeft - petSize.w  // 左边：同上
  const maxX = wa.x + wa.width - M - petLeft   // 右边：同上
  return {
    x: Math.min(Math.max(Math.round(x), minX), Math.max(minX, maxX)),
    y: Math.min(Math.max(Math.round(y), minY), Math.max(minY, maxY)),
  }
}
```

右键菜单里「🎬 她的动作」子树：✨ 回到默认 / 😊 表情{星星眼、圈圈眼、开心眼、

- 载荷格式 `act:expr:星星眼` / `act:motion:动作#6:1` / `act:swing:1` / `act:pat`

- 表情映射表（0~11）：回正、墨镜、问号、闪耀、星星眼、圈圈眼、开心眼、
  拽秋千1、拽秋千2、拽秋千回正、绳子开、绳子关。
- **动作语义（本手记的最后一条规则，也是最容易漏的一条）**：菜单里选任何新动作，
  都先**停下当前正在演的一切**（动作队列 + 挂着的表情 + 摸头计时 + 一直荡旗标），
  再演新的。实现是在每条菜单路径的头上打 `stopCurrent() + faceNeutral()`
  两个函数；`stopAllMotions()` 会连带清掉动作管理器的 state，
  所以**同一个动作再点一次也能从头重演**（不然会被「已在队列」挡掉、静默无反应）。
  三个函数的原文：

  ```js
  // 播一个具体动作。组名里带 #（动作#6），所以用「组 + 序号」而不是名字。
  const playMotion = (group, index) => {
    if (!model) return false
    // 先停下正在演的那个（含秋千），再把脸收回回正 —— 新动作自己不带表情，
    // 旧脸留着会压住动作本身（Wink 被星星眼压住就是这么来的）。
    stopCurrent()
    faceNeutral()
    let started = false
    // 优先级 3（FORCE）：默认的 NORMAL(2) 会被正在放的动作挡掉，而它拒绝时
    // 只走 logger.log —— 生产环境那个 logger 是哑的，我们这边一声不响。
    // （返回值也不能当成功：startMotion 先预订位置就返回，加载是异步的。）
    try { started = !!model.motion(group, index, 3) } catch (e) { started = false }
    console.log('[xilian][act] motion=' + group + '#' + index + ' requested=' + started)
    return started
  }

  // 停下正在演的一切。stopAllMotions() 会顺手把 current/reserved 全清掉
  //（MotionState.reset），所以同一个动作再选一次也能从头重演。
  const stopCurrent = () => {
    let busy = false
    try { busy = !!model.internalModel.motionManager.playing } catch (e) { /* ignore */ }
    if (busy || hitExprName !== null || patUntil !== 0 || swingOn) {
      console.log('[xilian][act] stop-current')
    }
    if (hitHoldTimer) { clearTimeout(hitHoldTimer); hitHoldTimer = null }
    hitExprName = null
    currentExpr = -1
    currentMotionRow = -1
    patUntil = 0
    // 秋千是被这一停停掉的 —— 状态位跟着落地，勾选框和实际才对得上。
    swingOn = false
    try { model.internalModel.motionManager.stopAllMotions() } catch (e) { /* ignore */ }
  }

  // 收回默认的脸。用 0 号「回正」而不是库的 resetExpression()：后者退到一张
  // 空表情，参数没人写就停在哪儿算哪儿；0 号是模型自己画好的回正脸。
  const faceNeutral = () => {
    currentExpr = EXPR.reset
    try { model.expression(EXPR.reset) } catch (e) { /* ignore */ }
  }
  ```

## 三、开机动画篇

### 3.1 装在启动链的哪一环

入口链：桌面图标 → VBS（隐藏控制台）→ `dsh-app.cmd`：

```
0)  动画最先起：start "" /b cmd /c "…\.dsh\splash\splash.cmd"   ← 谁也不等它
0b) 皮肤（best-effort）→ 0c) 桌宠（best-effort）
1)  端口守卫：127.0.0.1:3080 没起来 → 起本地服务并等
2)  open-app.ps1：msedge --app=… --start-fullscreen 全屏开界面
```

三条契约（2026-10-06 定稿）：

1. **动画最先起**；
2. **谁都不等它** —— 界面在动画背后并行打开、加载完等着，动画只是盖在上面
   （更早的版本等动画放完才开界面，每一秒都是纯等待，白等）；
3. **动画坏掉绝不能挡界面** —— `splash.cmd` 找不到 electron 运行时就直接退出、
   不写锁；页面级还有兜底（开场素材放不出来 → 显示一行「准备中」→ 自己收掉）。

`running.lock` 由 `splash.cmd` 唯一持有：写锁 → 跑 electron 到结束 → 删锁。
现在的链子不等它（上述契约 2），锁留给验证脚本读（「跑完锁要消失」）。
更早还有一版把开屏做进 DSH 页面本身的方案（页面内插件）、已卸下 ——
独立进程能盖住「服务还没起来」这段更早的等待，链路也更简单。

`splash.cmd` 全文（除文件头注释外就这么长；ASCII-only，CRLF）：

```bat
@echo off
REM DSH boot animation - the lock holder.
REM
REM This script is the ONLY writer: it creates the lock, runs Electron to completion
REM (no `start`, so the batch waits on it), then deletes the lock.
REM If the Electron runtime is missing this exits WITHOUT creating the lock, and
REM the UI opens right away -- a broken animation must never keep the app from starting.
REM ASCII ONLY: non-ASCII bytes in a .cmd get mis-decoded under a zh-CN code page.
setlocal
set "EXE=F:\work\dsh-xilian-pet\pets\xilian\electron\node_modules\electron\dist\electron.exe"
set "DIR=%~dp0"
set "LOCK=%DIR%running.lock"

if not exist "%EXE%" exit /b 0

REM %DIR% ends with a backslash; strip it so Electron gets a clean path.
set "APP=%DIR:~0,-1%"

echo %DATE% %TIME% > "%LOCK%"
"%EXE%" "%APP%"
del "%LOCK%" >nul 2>&1
exit /b 0
```

**为什么是独立进程而不是应用内 splash**：主流套路（electron-splashscreen 那一类）
要求「主窗口 ready-to-show 时收掉 splash」，而这里的界面是 Edge `--app=` 另开的
窗口、不归 Electron 管，没有那个回调。退一步：动画自己播完就关，
接口只剩文件系统级别的约定（锁 + 进程退出）。

### 3.2 素材不是「一个视频」：两层画面 + 三路声音

结构照抄原作者（Steam 创意工坊壁纸，见文末出处）：

| 文件 | 角色 |
|------|------|
| `intro.webm` | 开场画面，播一次（9.7s 4K） |
| `loop.webm` | 开场结束后的循环画面，一直转 |
| `atmos_loop.wav` | 氛围音，从第一秒就在响、一直循环 |
| `intro.wav` → `loop.wav` | 开场 BGM，放完接到循环 BGM |

- 少了 loop 只是少一层，还能看；**少了 intro 就真没得放了**（走兜底收掉）。
- 音量照抄原作者的折算：`VOL = { video: 0.80, bgm: 0.40, atmos: 0.48 }`
  （原作 master 80% × 视频 100% / bgm 50% / 氛围 60%，每路只有一个元素，
  直接乘出 volume 就等价）。

  ```js
  var VOL = { video: 0.80, bgm: 0.40, atmos: 0.48 }
  …
  // encodeURIComponent 是必须的：文件名里一旦有 '#'，浏览器会把它当成 URL 片段。
  function src(n) { return 'assets/' + encodeURIComponent(n) }
  ```
- 画面 `object-fit: cover` 铺满（会裁两侧）——这是原作者的选择；
  编码方面 Chromium 自带 VP9，不需要系统装「VP9 视频扩展」；HEVC 放不了。
- 两个必须的窗口设置：`show:false` + `ready-to-show` 再显示（否则视频首帧出来前
  会闪一下黑/白，开机动画最忌这个）；`autoplayPolicy: 'no-user-gesture-required'`
  （带声音的视频默认会被自动播放策略挡下，没人点过这个页面）。

### 3.3 退场编排：点击之后那两秒

点击/Esc 之后就进入 `exit()`，节拍全由**片段自己的 `ended` 事件**驱动，
不用墙钟去猜：

```
点击 → 提示文字 0.12s 速退 → touch 层 0.16s 叠化浮上来（糊住素材与录屏的质感差）
→ 播 touch.webm（23 帧 ≈0.77s：她收手 → 托星到脸前 → 闭眼 → 星芯点亮）
→ ended → bloom()：白光从星芯涨开（160ms）+ 20 片参数化花瓣
→ 停 400ms → 淡窗 650ms（音量与窗口透明度同步淡）
→ 主进程销毁窗口，界面从白光后面浮出来
```

- 常量都在一处：`EXIT = { bloomMs: 160, holdMs: 400, fadeMs: 650 }`；
  星芯锚点 `STAR = { x: 0.458, y: 0.22 }`（在 1920×1080 的片段上量的，
  bloom 按 `object-fit: cover` 反算成屏幕坐标，白光实心到 62% 半径，
  所以半径要除以 0.62 保证盖满四角）。

```js
var EXIT = { bloomMs: 160, holdMs: 400, fadeMs: 650 }
var STAR = { x: 0.458, y: 0.22 }

// 片尾那格（星芯点亮）冻着等白光 —— ended 一响就涨白。
touch.addEventListener('ended', function () {
  if (sent || bloomed) return
  bloomed = true
  bloom()
  // 白光涨完再等 400ms 才淡窗：官方那边白场漂着花瓣停了大半秒，界面才浮出来。
  setTimeout(function () { if (!faded) { faded = true; fadeOut() } }, EXIT.bloomMs + EXIT.holdMs)
})

function fadeOut() {
  // 全部声音一起淡到 0；窗口透明度归主进程拉：页面碰不到窗口。
  var els = [intro, loop, touch, atmos, bgmIntro, bgmLoop]
  var v0 = els.map(function (el) { return el.volume })
  var t0 = performance.now()
  var iv = setInterval(function () {
    var k = Math.min(1, (performance.now() - t0) / EXIT.fadeMs)
    for (var i = 0; i < els.length; i++) els[i].volume = v0[i] * (1 - k)
    if (k >= 1) clearInterval(iv)
  }, 33)
  try { window.splash.dissolve(EXIT.fadeMs) } catch (e) { finish('exit-no-dissolve') }
}
```

白光从星芯涨开 —— cover 反算 + 盖满四角的最小半径：

```js
function bloom() {
  var vw = window.innerWidth, vh = window.innerHeight
  // object-fit: cover 的反算：视频先等比缩到铺满，再居中裁掉溢出的部分。
  var sc = Math.max(vw / 1920, vh / 1080)
  var ax = STAR.x * 1920 * sc - (1920 * sc - vw) / 2
  var ay = STAR.y * 1080 * sc - (1080 * sc - vh) / 2
  // 白光是实心到 62% 半径的，除以它保证 scale=1 时四角全在实心白里。
  var R = Math.max(
    Math.hypot(ax, ay), Math.hypot(vw - ax, ay),
    Math.hypot(ax, vh - ay), Math.hypot(vw - ax, vh - ay)
  ) / 0.62
  var el = document.getElementById('bloom')
  el.style.left = ax + 'px'
  el.style.top = ay + 'px'
  el.style.width = el.style.height = (R * 2) + 'px'
  var s0 = 26 / R
  el.animate([
    …,   // 三帧关键帧：s0 → s0×2.1 → 1（略）
  ], { duration: EXIT.bloomMs, easing: 'cubic-bezier(.2,.7,.3,1)', fill: 'forwards' })
  petals(ax, ay)
}
```
- 花瓣数量、大小、角度、时长全由序号 `i` 推出来（**不用 Math.random**）——
  每次点击的花瓣雨都一样，可复现、可调试。
- 兜底：touch 片段加载失败 → 跳过片段直接走白光那一步；整段退场 4.5s 没走完 →
  立即收；主进程另有 5 分钟硬上限。
- 判定「退场走没走对」有个小坑：成功路径和 error 跳过路径**都会**打
  `dissolve: 650ms` 这行日志，光看日志分不出来。判据用
  **mousedown → dissolve 的间隔**：成功 ≈1.49s，error 路径 ≈0.56s。

### 3.4 四个只有跑起来才知道的坑

**坑一（最贵的）：不透明全屏窗口会让底下的界面被「停渲染」。**
症状：退场末尾有两段白 —— 第一段是 bloom（本意），第二段是界面窗在开屏窗口
销毁那一瞬**整窗空白约 0.4 秒**（先吐一帧窗底色浅白、再重画回来）。
根子在 Chromium 的遮挡计算：被一个**不透明**窗口完全盖住的窗口会被停渲染，
揭开时合成器重铺 surface，于是先白后画。修法两条：

```js
// 窗口从生下来就是「半透明层」：0.99（WS_EX_LAYERED 且 alpha<255 不算遮挡物）
win.setOpacity(0.99)
// 淡出从 0.99 往下拉，绝不能途经 1.0 —— 中间哪一帧抖回全不透明，
// 遮挡判定立刻成立、「第二段白屏」就回来
win.setOpacity(0.99 * (1 - k))
```

主进程里那条淡出（`splash-dissolve`，每 33ms 一档）：

```js
ipcMain.on('splash-dissolve', (_e, ms) => {
  const dur = Math.max(120, Math.min(2000, (ms | 0) || 420))
  if (dissolving) return
  dissolving = true
  log('dissolve: ' + dur + 'ms')
  const t0 = Date.now()
  const timer = setInterval(() => {
    if (!win || win.isDestroyed()) { clearInterval(timer); return }
    const k = Math.min(1, (Date.now() - t0) / dur)
    // 从 0.99 起淡，**绝不能途经 1.0** —— 遮挡判定的开关就是「alpha 是不是 255」。
    try { win.setOpacity(0.99 * (1 - k)) } catch (e) { /* ignore */ }
    if (k >= 1) { clearInterval(timer); finish() }
  }, 33)
})
```

验证方式：全桌面逐帧录屏 + 白度判据（`min(R,G,B)>230` 的像素占比）。
修前：淡出到 12.9% 后又**回跳 91.7%**、挂约 0.4s；修后单调下降
16.3% → 9.4% → 7.9% → 6.9%，两轮复现都干净。

**坑二：`resizable: false` 会在 Windows 上把全屏钉死。**
Electron 把「不可缩放」实现成给窗口钉死 min/max 尺寸，于是全屏那次 resize
也被挡住。证据链：手动拿屏幕 bounds 铺 1707×1067 → 实测窗口只有 812×608；
改成 `fullscreen: true` **还是** 812×608 —— 两种写法给出同一个数，
说明有东西在按住窗口。去掉 `resizable: false`（和 `maximizable: false`）之后正常。
这个病桌宠那边也犯过：`heal-size` 连着四次「523x703 → 480x670」一次都没成。

**坑三：`ready-to-show` 那一刻读到的窗口几何是切换中的中间值。**
要在显影后延迟再读一次才作数（代码里留了 `bounds@1.5s` 一行）。
窗口几何的读数别拿第一个数就下结论。

**坑四：`alwaysOnTop` 默认档盖不住任务栏。**
要 `win.setAlwaysOnTop(true, 'screen-saver')` —— 否则全屏动画下面露一条任务栏。
另外「全屏」是构造参数 + `ready-to-show` 里再要一次（构造时窗口还没显示，
不一定生效）。

### 3.5 「点按响应」不在素材里：录屏抢救与 4K 化

这是整段动画制作里最贵的认知：**点击后的「她回应你」那一段，壁纸素材里没有。**

- 素材只有：`intro.webm` 的开场（飞近 → 转身 → 指尖捧星展示）和 `loop.webm` 的
  展示姿态待机。素材尾巴往后怎么截，截到的都只是「她自顾自展示」的收尾 ——
  永远不会出现「回应你」的那一拍。前三版全栽在这。
- 真正的响应动作只在**官方录屏**里（她收手、托星升到脸前、闭眼恬静、星芯点亮
  → 白光）。识别出这一点之后，才有 `touch.webm`。
- 制作链：从无水印录屏切 **23 帧（29.97fps，≈0.77s，取自 60.87s 起）** →
  逐帧去水印（谐波扩散补丁，补丁区外逐像素与原帧一致、差 ≤1.5）→
  本地超分 `realesr-animevideov3 -s 2` 到 3840×2160（约 23 秒）→
  VP9 `-crf 12` 编码（≈41Mbps / 3.9MB，帧数/时长/帧率全不变）。
- **为什么必须 4K**：这台屏幕 2560×1600，cover 之后 1080p 是**放大 1.48 倍**
  显示（发糊的主因），4K 反而是缩小 0.74 倍 —— 和其它两段素材同规格。
  验收用「显示路径模拟」（两种版本都过一遍 cover→2560×1600 再比）：锐度
  +90%/+96%、帧间差不增、补丁区无闪烁、对位误差 2.64/255。
- 母版留档：超分后的 23 张 4K PNG（重新编码用）与超分前的 1080p 版本
  （回退用），都留在 `_probe\` 下。

### 3.6 部署契约与验证仪器

**部署**：`deploy.ps1` 幂等 —— 拷源码文件 + 素材（素材按缺失/大小变化，
46MB 不全拷）、把 `splash.cmd` 的换行归一为 CRLF，然后**断言契约**：

- `dsh-app.cmd` 里启动行在（`start "" /b cmd /c "…\splash\splash.cmd"`）；
- **没有**旧等待块（waitspin / waitgone / SPLASHLOCK 之类的名字）；
- 顺序：splash < skin < open-app；
- 全程 ASCII-only 检查。

```powershell
$launchLine = 'start "" /b cmd /c "C:\Users\ASUS\.dsh\splash\splash.cmd"'
if ($text.IndexOf($launchLine) -lt 0) {
  throw 'dsh-app.cmd does not start the splash (launch line missing)'
}
# 旧等待块一旦回来就炸（半旧半新的接线正是要防的）
if ($text -match 'waitspin|waitgone|SPLASHLOCK') {
  throw 'dsh-app.cmd carries the LEGACY wait block ... the UI opens in parallel.'
}
# 顺序：splash 必须排在真正花时间的家伙前面
$iSplash = $text.IndexOf($launchLine)
$iSkin   = $text.IndexOf('install-skin.ps1')
$iOpen   = $text.IndexOf('"C:\Users\ASUS\.dsh\open-app.ps1"')
if (-not ($iSplash -lt $iSkin -and $iSkin -lt $iOpen)) {
  throw ('order is wrong in dsh-app.cmd: splash@{0} skin@{1} open@{2} -- want splash < skin < open' -f $iSplash, $iSkin, $iOpen)
}
```

手改 `dsh-app.cmd` 容易改出「半旧半新」（比如把等待又加回去），
把契约写成**部署时的断言**，比事后翻日志找强。这个思路通用：
**能用结构性护栏防住的，别靠事后指标。**

**验证仪器**（都在 `C:\Users\ASUS\.dsh\repro\`，编号脚本）：

| 脚本 | 干什么 |
|------|--------|
| `21-probe-frames.ps1` | 加载**真** index.html + 真 preload，`CLICK_AT` 控点击时刻，之后 `capturePage` 110ms/帧，逐帧记 intro/touch 的 currentTime |
| `22-click-splash.ps1` | **真** SendInput 点击（PostMessage 的 WM_LBUTTONDOWN Chromium 不理） |
| `23-live-verify.ps1` | 全链一遍：等窗口 → 点击 → 等进程消失 → 只打本轮新增日志 |
| `24-screenwatch.ps1` | 全桌面逐帧 JPEG + times.csv（320 帧≈27s），盖得住整段退场 |

最终判据（对一条全链记录）：日志出现 `dissolve: 650ms`（= EXIT.fadeMs；
别的数就是走了 fallback 或旧路径）且**无** `done:`（那个是出错直收的路径），
随后 splash 进程 0、`running.lock` 消失。

## 四、经验总结（通用）

### 4.1 仪器先于猜测

看不见运行时状态，就只能猜 —— 而这两件成品里猜错的代价都不小（取景两轮、
退场三版）。做法：**先造读数，再改代码**。探针台（加载真页面、只桩窗口外壳）、
常驻日志（每个关键跳变一行）、逐帧录屏、捕获脚本 —— 这几样做齐之后，
几乎所有问题都变成「看一眼数字」。

### 4.2 先量噪声底，再谈变化

「她在动」不能只看动作前后的差异 —— 静置时她也在呼吸、眨眼、头发在晃。
秋千那次的正确姿势：先量**噪声底**（静置时两次指纹之差），再量动作后的差，
两者比。当初只量后者，误判成「113 块都在动」。**报数字要带两个东西：
乘数（是多还是少）与 WHICH（过阈值的是哪一块 mesh）；只说「动了」等于没说。**

### 4.3 三套坐标系，一次只换一处

同一块屏幕上有三套坐标：**物理像素**（2560×1600，截图脚本的世界）、
**DIP**（1707×1067 @150%，Electron 的 setBounds/getCursorScreenPoint 的世界）、
**CSS 像素**（页面内坐标、渲染进程报的 clientX/Y；画布的世界）。

- 换算只在一处发生（由 Electron 保证窗口↔DIP），页面内一律 CSS，
  **别自己乘 devicePixelRatio**；
- 截图/测量脚本 DPI awareness 要 **-4（PER_MONITOR_V2）**；用 -1（UNAWARE）
  拿到的是「虚拟化」的缩放画面 —— 尺寸看起来「对」（1707×1067），
  但坐标系错了，得出的每个结论都在错的空间里；
- 三个读数互相矛盾的时候，先怀疑「量的不是一个东西」，而不是继续调参。

### 4.4 静默失败是默认状态，不是异常

这套技术栈里最有杀伤力的失败全是无声的：404 被当「点了没反应」、
返回 `true` 其实没播、名字打错静默返回 false、参数写进去读不回来、
窗口 resize 被静默挡住……清单见第五节。两条通用对策：

- **返回值不可信**：凡是「先预约、后异步」的 API（`motion()`、下载、
  `play()`），它的返回值只说明「请求被接收」。要判成功，
  去读**系统里的活状态**（动作管理器、进程、文件），或让每个关键步骤
  自己留一行日志；
- **每个静默点都配一个读数**：点了没反应 → 加日志；改表情 → 读 currentExpr
  对比；下载 → 按字节数验收。

### 4.5 判据要对位；自检要覆盖「新的那一步」

- 判据要坐在**缺陷会暴露的位置**上：测「动画铺满全屏」，截图就要等视频真的
  出画（+3.9s）；在 +0.9s 截，只看到黑底窗口还报 99.5% 黑、「像成功」。
  测「白色回跳」，就要看**淡出尾段**的白度分布，不是开头。
- 自检漏掉的那一步 = 没测：有一版自检逐个试了表情、秋千、摸摸头，
  **唯独漏了「小动作前三个」** —— 于是它们坏了两天，是用户先发现的。

### 4.6 有状态循环要幂等；时间用事件，不用墙钟

- 凡是「定时器 + 状态比较 + 副作用」的循环，都要**同则不动**：每 2 秒的刷新
  和窗口 resize 曾经形成回路（两边对同一个数字的理解不一致 → 每 2 秒推一次
  尺寸 → 拖动时窗口一帧长 1px）。
- 时序编排跟着**事件**走（视频的 `ended`、进程退出），别 seek、不跟墙钟猜；
  需要连续数值时再用小步进合成（33ms 淡音量 / 60ms 轮询光标）。

### 4.7 Windows 手记

- **脚本语言环境**：截图脚本用 `powershell.exe`（5.1），pwsh 7 里
  System.Drawing 要显式引用、`Add-Type` 会报「找不到 Bitmap」；
  `.cmd` / `.ps1` 一律 **ASCII-only**（无 BOM 的源文件被按 cp936 读，
  中文路径会烂），需要中文就**从码点拼**（如 `[char]0x52A8 + [char]0x4F5C`）。
- **进程**：长驻进程要用 WMI（`Win32_Process.Create`）脱离调用者进程树 ——
  `Start-Process` 起的子进程会跟着终端一起被杀；终端抢焦点是死结，
  优先让用户手动点到目标状态，再让脚本接管。
- **权限**：程序从某目录启动就静默退出（无输出、无日志，exit 3）时，
  查目录的完整性标签 —— 被沙箱盖成 Low 的话，`icacls <dir> /setintegritylevel
  Medium /T` 修；exe 本身也要（它启动的子进程会继承 Low）。
- **合成输入**：`PostMessage` 的鼠标消息 Chromium 不理（要用真 SendInput）；
  真 SendInput 也到不了 `setIgnoreMouseEvents` 的穿透窗 —— 拖动那类交互
  没法用合成输入复现，只能靠日志。

## 五、坑点速查表

### A. 渲染与 Live2D

| 症状 | 原因 | 修法 |
|------|------|------|
| 模型清晰但缩在画布一角 | 给 canvas 设了 width/height **属性**，绘制缓冲与投影矩阵各算各的 | 只设 style 宽高 |
| 某些动作里她整块被裁没 | 剔除边界按画布矩形算，内容伸到画布外 | `cullable = false` |
| 整条渲染链加载失败：`process is not defined` | UMD 包求值期引用 `process.env.NODE_ENV` | 在加载它之前补最小 `window.process` 垫片 |
| file:// 下模型全 fetch 失败 | 浏览器禁止 file:// 页面 fetch 本地文件 | 自定义协议 + `loadURL`（见 2.4 坎二） |
| 点小动作没反应、控制台干净 | 文件名里的 `#` 被当 URL 片段 → 404；`motion()` 已提前返回 true；logger 生产环境哑 | 路径逐段编码（`%23`）；日志自己留 |
| 她从来不眨眼 | model3.json 的 `"Groups": []` 是空的 | 补 EyeBlink（ParamEyeLOpen/ROpen）+ LipSync 组 |
| 下载的五个动作文件全是 404 文本 / 半截 | `#` 当 URL 片段；404 可能看起来像 200 | 逐段 `EscapeDataString` + 按 API 字节数验收 |
| 日志 `requested=true` 但什么都没发生 | `motion()` 返回 Promise，`!!promise` 恒真；先预约后异步加载 | 判动作管理器状态，不信返回值 |
| 写进去的参数读不回来 | 更新末尾 `loadParameters()` 回写到原始值 | 记录写入次数，别回读 |
| `_isLoop` 是 false（Meta 里明明写了 Loop） | 这条加载链没让 Loop 生效 —— 动作演完就停 | 当事实用；要循环就自己重播 |

### B. 窗口与交互（桌宠 / 开屏共用）

| 症状 | 原因 | 修法 |
|------|------|------|
| 拖动时窗口每帧长 1px、宠物往下沉 | 2s 刷新回路 + 拖动中 setPosition 的 DIP 漂移 | resize 同尺寸幂等；拖动锁尺寸；位置 `setBounds` 全量写 |
| 拖动「跑掉」/ 拉不回来 / 放不高 | 用页面增量算位置；夹取夹的是窗口不是宠物；上边界多算气泡高 | 位置由主进程按光标算；按宠物本体夹、四边留 60px |
| 有时能拖动、有时一动不动 | 穿透死循环：收不到 mousemove 就不知道光标进来；是否复现看启动瞬间光标位置 | 判定权搬进主进程（轮询光标 vs 页面推的命中矩形） |
| 点「增大/减小」像没反应 | 主进程只改文件+发消息，真正改尺寸的刷新没人通知；渲染端还引用了改名的变量 | 收到消息立即刷新；`setScale` 从画幅重算 |
| 缩放上限算错、她越按越大越糟 | 上限按精灵图格子高（194）算，而 Live2D 的基准是 420 | 按渲染路径各自的基准算 |
| `heal-size` 连着四次全失败 | `resizable: false` 在 Windows 被实现成钉死 min/max | 别设 `resizable: false`（它会炸 setSize 和全屏） |
| 全屏窗口只有 812×608 | 同上；且 `ready-to-show` 读到的是切换中的中间值 | 去掉 resizable/maximizable:false；延迟 1.5s 再读几何 |
| 双击图标起了两只宠物 / 两层动画 | 缺进程级去重 | `requestSingleInstanceLock` |

### C. 开机动画

| 症状 | 原因 | 修法 |
|------|------|------|
| 退场后界面窗白 ~0.4s（「第二段白屏」） | 被不透明置顶窗完全盖住的窗口被 Chromium 停渲染，揭开重铺 surface | 生来 `setOpacity(0.99)`；淡出 `0.99×(1-k)`，绝不途经 1.0 |
| 动画第一帧前闪黑/闪白 | 窗口显示早于视频首帧 | `show:false` + `ready-to-show` 再 show |
| 动画没声音 | Chromium 自动播放策略挡下带声视频 | `autoplayPolicy: 'no-user-gesture-required'` |
| 全屏下面露一条任务栏 | alwaysOnTop 默认档盖不住任务栏 | `'screen-saver'` 档 |
| 「点按响应」怎么截素材尾巴都对不上 | 那段根本不在素材里 | 从官方录屏切（见 3.5） |
| 退场片段比其它素材糊 | 1080p 在这屏上放大 1.48 倍显示 | 本地超分 4K（变成 0.74 缩小） |
| PostMessage 模拟点击没反应 | Chromium 不理会 WM_LBUTTONDOWN | 真 SendInput |
| 合成鼠标事件拖不动桌宠（测不了） | 判定在主进程 + 穿透窗收不到合成事件 | 别用合成输入测拖动，用日志/探针 |
| 强杀桌宠后 launcher 说「她还活着」 | 心跳文件残留（15 秒窗口） | 删 `desktop_alive.json` 或等 15 秒 |

### D. 工具链与其它

| 症状 | 原因 | 修法 |
|------|------|------|
| 探针里动作静止不动 | 隐藏/被盖窗口 rAF 冻结 | `disable-renderer-backgrounding` + 关遮挡计算 + showInactive |
| pwsh 7 截图脚本报「找不到 Bitmap」 | System.Drawing 在 .NET Core 里拆包了 | 用 `powershell.exe`（5.1） |
| 截到 1707×1067「看起来对」但结论全错 | DPI awareness 用了 -1（虚拟化坐标空间） | 用 -4（PER_MONITOR_V2） |
| `.cmd`/`.ps1` 里中文路径乱码 | 无 BOM 源文件被按 cp936 读 | ASCII-only；中文从码点拼 |
| 程序一启动就静默退出（exit 3、无日志） | 目录被沙箱盖了 Low 完整性标签 | `icacls /setintegritylevel Medium /T`（exe 也要） |

| WMI 起的进程不继承环境变量 | WMI 的进程环境是干净的 | 参数另写一个 launcher 文件（或走命令行参数） |

## 六、当模板用

### 6.1 换一个 Live2D 模型

1. **先确认授权**（能改吗、能再分发吗、商用吗、要署名吗）—— 授权不对，后面全白做。
2. 模型放 `pets\xilian\live2d\<名字>\`（不进 git），仿照
   `tools/fetch-cyrene-model.ps1` 的下载+校验方式。
3. 过一遍两个**模型文件补丁**（这两条换来换去都会遇到）：
   - `model3.json` 里 `"Groups"` 为空 → 补 `EyeBlink`（ParamEyeLOpen/ROpen）与
     `LipSync`（ParamMouthOpenY），不然永远不眨眼；
   - 动作/表情路径里带 `#` 等 URL 特殊字符 → 写进 model3.json 时用 `%23`
     （运行时加载器不会替你编码；服务端 handler 会解码）。

     补丁本身（`tools/fetch-cyrene-model.ps1`，逐字替换、幂等、BOM-less）：

     ```powershell
     # BOM-less on purpose: a leading BOM makes JSON.parse throw inside the app.
     $text = [System.IO.File]::ReadAllText($model3)
     $before = $text
     $text = $text.Replace($DONGZUO + '#6_', $DONGZUO + '%236_')
     $text = $text.Replace(
       '"Groups": [],',
       '"Groups": [{"Name": "EyeBlink", "Ids": ["ParamEyeLOpen", "ParamEyeROpen"]}, {"Name": "LipSync", "Ids": ["ParamMouthOpenY"]}],')
     if ($text -ne $before) {
       [System.IO.File]::WriteAllText($model3, $text, (New-Object System.Text.UTF8Encoding($false)))
     }
     ```
4. 改两张表：表情映射（名字→编号）与命中区表（HitAreas 名字 → 反应）。
   **都按名字、不按编号。**
5. 跑一遍 `_probe`：看 `[xilian][l2d] bounds` 的取景读数、命中区地图、
   九区演练、装配单（参数/部件清单）—— 全部在日志里，一次看完。
6. 显示基准高度按模型内容改（`PET_L2D_HEIGHT`），缩放会自动从画幅重算。

### 6.2 换一套开屏素材

1. 五个文件照 3.2 的表格备齐（intro / loop / touch 画面 + 三路声音），
   音量沿用 `{video .80, bgm .40, atmos .48}` 的折算思路。
2. 退场片段（touch）：如果没有现成的，就从你能找到的最高清源里切 ——
   但先诚实地确认「响应动作」在不在源素材里（我们在壁纸素材上找了三个版本，
   它真的不在）。切点对齐到「点亮前一格」，剩下的白光交给 bloom。
3. 在片段上重新量星芯位置（或任意你要的爆点），改 `STAR`。
4. 保持这几条不动：`object-fit: cover`、`ended` 事件驱动、花瓣不用 random、
   `opacity 0.99` 出生 + 淡出不途经 1.0。
5. 换了分辨率先算一遍显示倍率（放大 = 糊），不够就超分/重编码（VP9）。
6. 先跑抽帧探针（21 号脚本），再 `deploy.ps1`，再全链验证（23 号脚本）。

### 6.3 换一个宿主应用（把开屏接到别人的启动链上）

三条原则原样搬：

1. **最先起、谁也不等** —— 动画盖住的必须本来就要发生的等待（比如服务启动），
   不能是「为了放动画而多等」；
2. **坏动画不能挡主流程** —— 起动画的那条命令永远退 0；素材缺失就自己收掉；
   主流程里没有任何一行等它；
3. **入场锁由动画侧持有**（动画是唯一写者），给验证工具留「正在播」的信号。

具体接法：仿 `splash.cmd`（找到运行时 → 写锁 → 跑 → 删锁 → 永远退 0）
+ 一行 `start "" /b cmd /c "…"` 放在启动链最前面。部署脚本里把
「启动行存在、旧等待不存在、顺序正确」写成断言（见 3.6）。

### 6.4 总清单（抄走版）

- [ ] 窗口：无边框 / 透明 / 置顶档 / `show:false`+`ready-to-show` /
      **不设 resizable:false**
- [ ] 要 fetch 本地文件 → 自定义协议（ready 前注册、前缀校验防穿越）
- [ ] 本地渲染库先补 `process` 垫片；脚本顺序钉死
- [ ] 要点击穿透 → 判定权放主进程（轮询光标 vs 页面推矩形）
- [ ] 拖动：抓取偏移 + 主进程算位置 + 拖时锁尺寸 + `setBounds` + 按内容夹取
- [ ] 叠在全屏上的窗口：`setOpacity(0.99)` 出生；淡出不途经 1.0
- [ ] 逐帧动画的节拍按内容设计（哪些帧是稳态、哪些是事件帧）
- [ ] 任何「先预约后异步」的 API：不信返回值，读活状态 + 自留日志
- [ ] URL 里的特殊字符（`#`）处处编码；下载按字节数验收
- [ ] 有状态循环幂等（同则不动）；时序跟事件不跟墙钟
- [ ] 判据坐在缺陷会暴露的位置；自检覆盖每一个新增步骤
- [ ] 脚本 ASCII-only；截图用 PowerShell 5.1；DPI awareness -4
- [ ] 长驻进程 WMI 脱离；结构性护栏写进部署断言
